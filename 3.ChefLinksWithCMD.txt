What is CHEF ---->
Chef is a open-source configuration management and infrastructure automation tool used in DevOps and IT operations. It treats infrastructure setup as software code—a concept known as Infrastructure as Code (IaC).

  (Laptop)            (Local)         (Server)          (EC2 Instance)         (EC2 Instance)

                                Amazon Linux Workflow

    ┌───────────────┬─────────────────────┼─────────────────────┬───────────────┐
    ↓               ↓                     ↓                     ↓               ↓
 1. DEVELOP      2. TEST               3. UPLOAD             4. BOOTSTRAP    5. CONVERGE
    │               │                     │                     │               │
  Workstation     Workstation          Chef Server           EC2 Machine     EC2 Machine
  (Write code)   (Test code)          (Store code)          (Install Chef)  (Apply code)

STEP 1: DEVELOP (On your Workstation)
chef generate cookbook my_app                                                   📁 Create cookbook
chef generate recipe my_app                                                     📝 Create recipe
chef generate recipe my_app default                                             📝 Write code inside recipe

How include_recipe Works in default.rb
When you create a cookbook, Chef automatically creates a file named recipes/default.rb.

# Inside recipes/default.rb
# 1. Include a recipe from the SAME cookbook (apache-book)
include_recipe 'apache-book::install'
include_recipe 'apache-book::config'
include_recipe 'apache-book::service'
# 2. Include a recipe from a DIFFERENT cookbook (e.g., test-book)
include_recipe 'test-book::default'

STEP 2: TEST (On your Workstation)
chef exec ruby -c /path/to/cookbook-recipe.rb                                   🔍 Test syntax
chef-client -zr "recipe[my_app]"                                                🧪 Test code locally without server

STEP 3: UPLOAD (To Chef Server)
Transfer Key to Workstation using WinSCP (Move node-key.pem to your workstation working directory).

Verify Server Trust:
chef ssl check                      # 🔐 Ensure secure trust with Chef Server

Upload Cookbooks:
knife cookbook upload my_app        # ⬆️ Push app cookbook to server
knife cookbook upload apache-book   # ⬆️ Push apache cookbook to server

STEP 4: BOOTSTRAP (Connect EC2 Instance to Chef Server)
Provision Node 1 (EC2 Instance) with User Data script for automated background convergence:

#!/bin/bash
sudo su
yum update -y
echo " * * * * * root chef-client " >> /etc/crontab/
(💡 Think: ⏰ Auto-Sync — Automatically runs chef-client every minute via cron)

meaning:
*  *  *  *  *
 │  │  │  │  │

 │  │  │  └──────── Month (1 - 12)
 │  │  └─────────── Day of month (1 - 31)
 │  └────────────── Hour (0 - 23)
 └───────────────── Minute (0 - 59)

Bootstrap Node from Workstation:
knife bootstrap <EC2_IP> --ssh-user ec2-user --sudo -i node-key.pem -N node1     ⚡ Connecting and Install Chef on EC2 node
knife node run_list add node1 "recipe[apache-book]"                              ➕ Assign recipe or cookbook to node's run-list
knife node list                                                                  🔍 Query all nodes on server
knife node show <node_name>                                                      🔍 View node run-list & attributes

STEP 5: Creating & Defining Roles (chef-repo/roles/)
Bundling a specific run-list of recipes and custom books together into a single role
Inside the roles/ directory of your chef-repo, create a role definition file (e.g., devops.rb):

vi roles/devops.rb ---->
name 'devops'
description 'This is to create the devops role file'
run_list "recipe[apache-book1::recipe1]","recipe[test-book2::recipe3]"

chef exec ruby -c roles/devops.rb      🔍 Validate Ruby syntax of role file
chef-client -zr "recipe[my_app]"       🧪 Test locally without server connection
chef ssl check                         🔐 Ensure secure trust with Chef Server
knife cookbook upload apache-book      ⬆️ Push cookbook to server
knife role from file roles/devops.rb   🎭 Upload/Update role file to Chef Server
knife role list                        🔍 Verify role uploaded successfully
knife node run_list add node1 "role[devops]"      ➕ Assign role to node's run-list

Role explain:
When you update Chef cookbooks in your local repository, you must upload those updates to the Chef Server so they are available to your nodes. 
Since cookbooks change frequently with daily edits, you will upload them on a daily basis. 
In contrast, roles change less often and do not require multiple frequent uploads. 
Once you define the run_list inside your role.rb to specify which recipes should run, you upload the role to the server. 
Finally, you assign that role to your target node. 
When the node runs chef-client, it fetches the assigned role from the server, evaluates the run_list, and executes the specific recipes on your infrastructure/vm

Think of setting up your servers like managing a restaurant kitchen:

📜 RECIPE                    📚 COOKBOOK                      🎭 ROLE
(Individual Dish Steps)         (Categorized Menu)          (Full Combo Meal / Job)
           │                             │                             │
           ▼                             ▼                             ▼
 How to cook French Fries       Appetizer Cookbook            "Chef Special Combo"
 How to cook Burger             Entree Cookbook            (Burger + Fries + Soda)
 How to assemble Soda           Beverage Cookbook                      │
                                                                       ▼
                                                             Assigned to Customer Node

Multi-Package Loop Syntax (Iterative Package Installation)
To write clean, DRY (Don't Repeat Yourself) code for installing multiple packages inside a single recipe:

%w(httpd git tree unzip docker).each do |p|
  package p do
    action :install
  end
end

INSPECT   ───>   MANAGE   ───>   UPLOAD   ───>   BOOTSTRAP
(Query)         (Modify)        (Publish)        (Provision)

──────────────────────────────────────────────────────────────────────────────────────────

                                   KNIFE WORKFLOW
                                         │
       ┌─────────────────────────────────┼─────────────────────────────────┐
       ↓                                 ↓                                 ↓
    INSPECT                            MANAGE                           DEPLOY
       │                                 │                                 │
 knife node list                  knife node run_list add           knife cookbook upload
 knife cookbook list              knife role from file              knife bootstrap <IP>
 knife ssl check                  knife data bag create             knife node delete

──────────────────────────────────────────────────────────────────────────────────────────

knife node list                                                                  🔍 Query all nodes on server
knife node show <node_name>                                                      🔍 View node run-list & attributes
knife node run_list add <node_name> "recipe[book1]"                             ➕ Assign recipe to node's run-list
knife node run_list remove <node_name> "recipe[book1]"                          ➖ Remove recipe from node's run-list
knife node delete <node_name> -y                                                 🗑️ Delete node record from server

──────────────────────────────────────────────────────────────────────────────────────────

knife cookbook list                                                              📚 Query all uploaded cookbooks
knife cookbook show <book_name>                                                  🔍 View cookbook versions on server
knife cookbook upload <book_name>                                                ⬆️  Publish local cookbook to server
knife cookbook upload -a                                                         ⬆️  Publish ALL cookbooks to server
knife cookbook delete <book_name> -y                                             🗑️ Delete cookbook from server

──────────────────────────────────────────────────────────────────────────────────────────

knife role list                                                                  📋 Query all server roles
knife role show <role_name>                                                      🔍 View role definition
knife role from file <path/to/role.json>                                        ⬆️  Upload role to server

──────────────────────────────────────────────────────────────────────────────────────────

knife data bag list                                                              🔐 Query all data bags
knife data bag create <bag_name>                                                 📁 Create new data bag on server
knife data bag show <bag_name> <item_name>                                       🔍 Read item contents from bag

──────────────────────────────────────────────────────────────────────────────────────────

knife ssl check                                                                  🔒 Verify connection to Chef Server
knife client list                                                                💻 Query API client keys on server
knife bootstrap <IP> -N "web-1" -x <user> -P <pass> --sudo                      ⚡ Install client & join server
knife bootstrap <IP> -N "web-1" -i <pem_key> -x <user> --sudo                    ⚡ Bootstrap using SSH key file

The simple difference b/w Node and Client :

         NODE                                                CLIENT
┌──────────────────────┐                           ┌──────────────────────┐
│     THE COMPUTER     │                           │     THE PASSWORD     │
│   (Hardware/Specs)   │                           │     (API ID / Key)   │
└──────────────────────┘                           └──────────────────────┘
 Stores what to install                             Allows the computer to 
 (IP address, run-list)                             talk to Chef Server

──────────────────────────────────────────────────────────────────────────────────────────

knife node list                                                                  🖥️ Shows list of SERVERS (web-1, db-1)
knife client list                                                                🔑 Shows list of PERMISSIONS (Keys/Users)

──────────────────────────────────────────────────────────────────────────────────────────

Think of it like an Employee in a building:

• NODE   = The Employee's Desk & Work Tasks (What they do)
• CLIENT = The Employee's ID Badge (Allows them into the building)

──────────────────────────────────────────────────────────────────────────────────────────

⚠️ IMPORTANT:
When you delete a server, you must delete BOTH:

knife node delete web-1 -y                                                       🗑️ Deletes the server details
knife client delete web-1 -y                                                     🗑️ Revokes the API key

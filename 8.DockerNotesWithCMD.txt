What is Docker ---> 
Docker is a tool that packages an application along with all its code, libraries, and dependencies into a single, standardized unit called a
container.

Docker's main advantages in short:
Fixes "Works on my machine": Runs identically everywhere—laptop, test server, or cloud.
Saves Memory & Money: Uses far less RAM and CPU than heavy Virtual Machines.
Blazing Fast: Boots applications in seconds instead of minutes.
Instant Team Onboarding: Lets new devs start working instantly with one command instead of spending hours configuring setups.

Docker's main limitations in short:
Shared Security: Containers share the host OS engine, so one breach can risk the whole system.
Temporary Memory: Data disappears when a container stops unless saved to an outside folder.
No Desktop GUIs: It is built for background services, not visual apps like video games or media players.
OS Restrictions: You cannot run Windows-only software directly on a Linux host.
Complex at Scale: Managing hundreds of containers requires heavy extra tools like Kubernetes.

  • Virtualization : Hardware-level (Cloud Hypervisor)
  • OS Requirement : Full Guest OS per EC2 instance

  • Memory Usage   : High (GBs of RAM)
  • Where it Runs  : In Amazon's Cloud Data Centers

How to Remember Everything (The Apartment vs. House) ----->

VMware / AWS EC2 = Full Houses 🏡: 
Each VM is like building a separate, standalone house. Each house requires its own plumbing, wiring, structure, and foundational setup (Guest OS).

Docker = Apartment Units 🏢:
Docker is like an apartment building. All apartments share the building's main plumbing, water, and structural foundation (Host OS Kernel), but each
room is isolated, secure, and self-contained inside.

🍴 Concept Breakdown : 
📜 Dockerfile (The Written Recipe) - > Role: Plain-text step-by-step instructions.
Summary: Tells Docker how to install dependencies and run your code.

🧊 Docker Image (The Frozen Batter) - > Role: Read-only blueprint built from the Dockerfile.
Summary: Stays frozen in storage—cannot be changed while running.

📦 Docker Container (The Baked Cake) - > Role: A live, running app launched from an Image.
Summary: You can start, stop, or throw it away without ruining the original Image.

⚙️ Docker Daemon (The Head Chef) - > Role: Background service (dockerd) on the host server.
Summary: Listens for commands and builds/runs all containers.

💻 Docker Client (The Waiter) - > Role: Your terminal CLI where you type commands.
Summary: Takes orders like docker run and hands them to the Daemon.

🖥️ Docker Host (The Kitchen Building) - > Role: The physical machine or cloud VM (e.g., EC2).
Summary: Provides the actual resources (CPU, RAM, Disk) for the Docker engine.

🏪 Docker Registry / Hub (The Central Supermarket) - > Role: Public/private cloud library for images.
Summary: Where you download pre-built bases (like Python, Node, or MySQL) instead of building from scratch.

🐳 Docker Command Cheat Sheet

# === 🛠️ ENGINE & SERVICE CONTROL ===
service docker start                        ▶️ Start Docker engine background service
service docker stop                         ⏹️ Stop Docker engine background service
service docker status                       🔍 Check if Docker background daemon service is running/active
docker info                                 ℹ️ Display system-wide Docker setup details

# === 📦 DOCKER HUB & REGISTRY ===
docker search ubuntu                        🔍 Find public images on Docker Hub
docker pull ubuntu:22.04                    📥 Download image from hub to local machine
docker push username/app:1.0                📤 Upload local image to public/private registry

# === 🚀 CONTAINER CREATION & RUNTIME ===
docker run -it --name web ubuntu /bin/bash  🏁 Create & enter container with interactive terminal
docker run -d -p 8080:80 --name web nginx   🌐 Run container in background with host port mapped
docker exec -it web /bin/bash               🚪 Open interactive bash shell inside running container

=== 📦 FROM CONTAINER (docker commit) Use to create image using container ===
docker commit <container_id> newimagename   📸 Save a running container as a new image

# === 🔍 MONITORING & AUDITING ===
docker ps                                   🟢 List only currently active/running containers
docker ps -a                                📋 List all containers including stopped and exited
docker logs -f web                          📜 Stream live stdout logs from target container
docker diff web                             🕵️ Show file modifications (A=Add/Append, C=Change, D=Delete)
docker stats                                📊 View real-time CPU, RAM, and network usage

# === 📁 FILES & VOLUMES ===
docker cp app.conf web:/etc/nginx/          ↗️ Copy local file into container filesystem
docker cp web:/var/log/nginx/access.log .   ↘️ Copy container file back to host machine
docker run -v /host/dir:/container/dir app  💾 Mount host directory for persistent data

# === 📝 DOCKERFILE & IMAGE BUILDING ===
vi Dockerfile                               ✏️ Open editor to design image specifications
docker build -t username/app:1.0 .          🏗️ Build custom image from current directory Dockerfile

# === 🧹 LIFECYCLE & CLEANUP ===
docker stop web                             ⏸️ Gracefully halt a running container
docker start web                            ▶️ Resume execution of a stopped container
docker attach web                           🔌 Connect terminal directly to running container process
docker rm web                               🗑️ Delete a stopped container instance
docker rm -f web                            💥 Forcefully kill and delete running container
docker rmi ubuntu:22.04                     ❌ Delete local container image
docker container prune -f                    🧹 Wipe all stopped containers & unused cache

docker stop $(docker ps -q): Dynamically stops all running containers.

docker start $(docker ps -a -q): Starts all containers (including stopped ones).

# === 📝 DOCKERFILE COMMANDS REFERENCE ===(Command should be used in capital)
FROM ubuntu:22.04                           🏷️ Define base image layer to build upon
RUN apt-get update && apt-get install -y py3⚙️ Execute build commands to install dependencies
WORKDIR /app                                📂 Set internal working directory for commands
COPY . /app                                 📥 Copy host files into container filesystem
ADD archive.tar.gz /app                     📦 Copy host files AND auto-extract archives/URLs
ENV APP_PORT=8080                           🌐 Set persistent environment variables inside
EXPOSE 8080                                 🔌 Document container listening port for mapping
VOLUME ["/app/data"]                        💾 Declare mount point for host storage binding
USER appuser                                👤 Set non-root system user for execution safety
CMD ["python3", "main.py"]                  🚀 Default executable command when container starts
ENTRYPOINT ["python3"]                      🔒 Fixed executable base that accepts arguments

📝 Example Dockerfile (vi Dockerfile)
FROM ubuntu:22.04
RUN apt-get update && apt-get install -y python3
WORKDIR /app
COPY . /app
ENV PORT=8080 (like a key,value pair)
EXPOSE 8080
CMD ["python3", "app.py"]

F ➔ FROM       (Where do I start?)
R ➔ RUN        (What do I install?)
W ➔ WORKDIR    (Where do I stand?)
C ➔ COPY       (What files do I bring in?)
C ➔ CMD        (What do I run when powered on?)
💡 CMD vs ENTRYPOINT Tip:
CMD = Easily overridden when running docker run image <new_cmd>.
ENTRYPOINT = Fixed baseline binary that treats docker run inputs as parameters(ENTRYPOINT has high priority then CMD)

# --- 1. Volume Creation via Dockerfile Setup ---
docker build -t my-amazon-image .                                                    🛠️ Build custom image from Dockerfile & here (.) state as current directory
docker run -it --name container1 my-amazon-image //bin/bash                          🚀 Run container using Dockerfile volume
docker run -it --name container2 --privileged=true --volumes-from container1 amazonlinux:latest //bin/bash  🔗 Mount volumes from container1 into container2

# --- 2. Container Management & Shell Attachment ---
docker start container1                    ▶️ Start an existing stopped container
docker attach container1                   🔌 Attach terminal input/output to running container/move me in container

# --- 3. Volume Creation via CLI (-v and --volumes-from) ---
docker run -it --name container3 -v /sharing_volume_name ubuntu //bin/bash         📦 Create container3 with CLI volume directory
docker run -it --name container4 --privileged=true --volumes-from container3 amazonlinux //bin/bash  🔗 Mount volumes from container3 into container4

# --- 4. Host to Container Mounting Examples ---
WINDOWS / BASH               💻 docker run -it --name hostcon -v "C:/Users/Rafi/Videos/LinuxRunCLI_Dir:/hostdir" --privileged=true amazonlinux //bin//bash
LINUX / EC2 INSTANCE         🐧 docker run -it --name hostcon -v "/home/ec2-user:/hostdir" --privileged=true amazonlinux //bin//bash

Command meaning :
DOCKER RUN                               🐳 Creating and starting a brand new container from an image
INTERACTIVE TERMINAL (-it)               💻 Opening an interactive terminal session inside container
CONTAINER NAME (--name hostcon)          🏷️ Assigning custom name 'hostcon' to the container
VOLUME MOUNT (-v)                        📁 Sharing host directory with container's /hostdir path
ROOT PRIVILEGES (--privileged=true)      ⚡ Giving container full access to host hardware/system
IMAGE NAME (amazonlinux)                 📦 Using official Amazon Linux OS image from Docker Hub
SHELL ENTRY (//bin//bash)                🚪 Launching Bash shell (double slashes prevent Git Bash path errors)

❓ EXPOSE vs. Port Mapping (-p) Difference ----
EXPOSE (in Dockerfile)                        📝 DOCUMENTATION ONLY: Declares which ports the container listens on at runtime.
                                              ⚠️ DOES NOT open ports to the outside world or host machine!

PORT MAPPING (-p host:container)             🔌 ACTUAL NETWORK BINDING: Redirects traffic from host machine port to container port.
                                              ✅ MAKES CONTAINER ACCESSIBLE via browser/network (e.g. http://localhost:80)!

# Example comparison:
EXPOSE 80                                     # Tells developers: "This image runs a service on port 80"
docker run -p 8080:80 ubuntu                  # Actually forwards http://host-ip:8080 to container's port 80

==============🏢 Imagine a Factory(Exec vs. Attach Difference) ==============
Your Docker container is like a running factory:
The main application (like Apache or Nginx) is the factory engine running inside.

1️⃣ docker exec (Adding a New Guest Entrance 🚪) ------ docker exec -it techserver //bin/bash
What happens: You step into the factory through a back door to look around or fix something.
When you leave (exit): You just leave through the back door. The factory engine keeps running!
Use case: Checking files, installing software, troubleshooting.

2️⃣ docker attach (Grabbing the Factory Control Panel 🔌) ----- docker attach techserver
What happens: You plug directly into the main factory engine switch.
When you leave (exit): You shut off the main engine switch! The entire factory stops!
Use case: Watching live logs directly from the main running app.
